# 5.4. Пагинация и сортировка

> **Важное примечание:** Перед началом реализации необходимо детально изучить всю документацию в папке `ABOUT/` и её подпапках (`API_SPEC_ADMIN`, `API_SPEC_FRONT`), а также ознакомиться с уже описанными пунктами в папке `spec/` для полного понимания контекста и текущих архитектурных решений.

Раздел фиксирует единый подход к пагинации, сортировке и мета‑данным в ответах.

## 5.4.1 Query‑параметры

Для списков используются стандартные параметры:

- `page` — номер страницы (начиная с 1).
- `limit` — количество элементов на странице.
- `search` — поисковая строка (если применимо).
- `sortBy` — поле сортировки (если применимо).
- `sortOrder` — порядок сортировки: `asc | desc`.

> **Важно:** точный набор параметров и значения по умолчанию определяются спецификациями API и могут отличаться по эндпоинтам. Если в `API_SPEC_*` указан `pageSize` (например, для leaderboard), необходимо следовать этому контракту.

## 5.4.2 Формат ответа для пагинируемых списков

Стандартный формат:

```json
{
  "data": [ ... ],
  "meta": {
    "total": 100,
    "page": 1,
    "limit": 20,
    "totalPages": 5
  }
}
```

- `totalPages` = `Math.ceil(total / limit)`
- Если API‑спецификация задаёт иной формат (`pagination` вместо `meta`) — используется именно он.

## 5.4.3 Сортировка

- Список допустимых полей сортировки задаётся в спецификациях конкретных эндпоинтов.
- Недопустимые параметры сортировки возвращают ошибку:
  - `code: INVALID_SORT_PARAMETER` (см. `API_SPEC_FRONT/12-error-codes.md`).

## 5.4.4 Значения по умолчанию

- **Admin API:** значения по умолчанию берутся из `ABOUT/API_SPEC_ADMIN/*` и `implementation-notes.md`.
- **Frontend API:** значения по умолчанию берутся из `ABOUT/API_SPEC_FRONT/*`.
