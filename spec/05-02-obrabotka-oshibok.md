# 5.2. Обработка ошибок

> **Важное примечание:** Перед началом реализации необходимо детально изучить всю документацию в папке `ABOUT/` и её подпапках (`API_SPEC_ADMIN`, `API_SPEC_FRONT`), а также ознакомиться с уже описанными пунктами в папке `spec/` для полного понимания контекста и текущих архитектурных решений.

Раздел фиксирует единый формат ошибок и требования к обработке исключений для Frontend API и Admin API.

## 5.2.1 Единый формат ошибки (Envelope)

Все ошибки должны возвращаться строго в следующем формате:

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable error message",
    "details": {}
  }
}
```

- `code` — машинный код ошибки (строго из файлов спецификаций).
- `message` — человекочитаемое описание.
- `details` — опционально (для валидации и дополнительных параметров).

## 5.2.2 Источник кодов ошибок

**Источник истины:**

- Frontend API: `ABOUT/API_SPEC_FRONT/12-error-codes.md`
- Admin API: `ABOUT/API_SPEC_ADMIN/error-codes.md`

Если код отсутствует в спецификациях — его нельзя использовать без обновления документации.

## 5.2.3 Требование к ExceptionFilter

В обоих API должен быть реализован **глобальный `ExceptionFilter`** в NestJS, который:

- Перехватывает все ошибки (`HttpException`, `ValidationError`, неожиданные ошибки).
- Приводит их к единому Envelope‑формату.
- Маппит HTTP статус на `error.code` согласно спецификации.
- Не раскрывает внутренние стеки и системные детали клиенту.

## 5.2.4 Валидация и ошибки 422/400

- Ошибки `class-validator` должны возвращаться с `code: VALIDATION_ERROR`.
- Поле `details` содержит список/карту ошибок по полям:
  - пример: `{ "email": "Invalid email", "password": "Too short" }`
- HTTP статус:
  - `422 Unprocessable Entity` (frontend спецификация допускает 422),
  - `400 Bad Request` — если это указано в admin‑спецификации.

## 5.2.5 Ошибки доступа

- `401 Unauthorized` → `UNAUTHORIZED` или `INVALID_CREDENTIALS` (в зависимости от контекста).
- `403 Forbidden` → `FORBIDDEN` или `INSUFFICIENT_PERMISSIONS`.

## 5.2.6 Внутренние ошибки

- Любая непредвиденная ошибка должна возвращаться как:
  - `500 Internal Server Error`
  - `code: INTERNAL_ERROR` (Admin) или `INTERNAL_SERVER_ERROR` (Frontend)
- Подробности ошибки логируются на сервере, но не возвращаются в ответе.
