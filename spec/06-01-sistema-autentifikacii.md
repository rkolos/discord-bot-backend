# 6.1. Система аутентификации

> **Важное примечание:** Перед началом реализации необходимо детально изучить всю документацию в папке `ABOUT/` и её подпапках (`API_SPEC_ADMIN`, `API_SPEC_FRONT`), а также ознакомиться с уже описанными пунктами в папке `spec/` для полного понимания контекста и текущих архитектурных решений.

Раздел описывает требования к пользовательской и админской аутентификации.

## 6.1.1 Пользовательская аутентификация (Frontend API)

### JWT Access Token

- Короткоживущий токен (например, 15–60 минут).
- Передается в `Authorization: Bearer <token>`.

### Refresh Token

- Долгоживущий токен, хранится в **HttpOnly Cookie**.
- В базе хранится **только хэш** токена (см. таблицу `refresh_tokens` в `spec/04-01-postgresql.md`).
- Для каждой ротации создается новая запись, старая помечается `revoked_at`.

### Ротация и отзыв

- `POST /api/auth/refresh` должен:
  - проверить валидность refresh‑токена;
  - создать новый refresh‑токен;
  - отозвать предыдущий.
- `POST /api/auth/logout` должен:
  - отозвать текущий refresh‑токен;
  - очистить cookie на клиенте.
- При подозрении на компрометацию — пометить токены `revoked_at` и требовать повторный вход.

## 6.1.2 Discord OAuth2

- Вход через `GET /api/auth/discord` и `GET /api/auth/discord/callback` по спецификации `ABOUT/API_SPEC_FRONT/01-authentication.md`.
- После обмена `code` → `access_token`:
  - получить профиль пользователя Discord;
  - связать/создать пользователя в `users`;
  - выдать JWT и refresh‑токен согласно правилам выше.

## 6.1.3 Админская аутентификация (Admin API)

- Авторизация через `POST /api/auth/login` (см. `ABOUT/API_SPEC_ADMIN/auth.md`).
- Возвращается JWT, используемый в `Authorization: Bearer <token>`.
- Отзыв токена при `POST /api/auth/logout`.
- Админские учетные записи хранятся в `admin_users` (см. `spec/04-01-postgresql.md`).

## 6.1.4 Требования безопасности

- Не возвращать refresh‑токены в JSON‑ответах (только HttpOnly Cookie).
- Хранить пароли админов в `password_hash` (bcrypt/argon2).
- Логи аутентификации должны скрывать чувствительные данные.
