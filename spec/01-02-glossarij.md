# 1.2. Глоссарий

Данный документ определяет ключевые термины, используемые в проекте Server.Ninja, для обеспечения единого понимания терминологии всеми участниками разработки.

## Основные термины

### Guild (Гильдия)
**Определение:** Discord сервер (Discord Server)

**Описание:** 
- Основная единица организации в Discord
- В контексте системы Server.Ninja — это сервер, подключённый к платформе для сбора аналитики и управления ботами
- Каждая гильдия имеет уникальный идентификатор (guild_id)
- Гильдия может принадлежать пользователю или команде (Team)

**Синонимы:** Discord Server, Сервер

---

### Counter (Каунтер / Счётчик)
**Определение:** Динамический счётчик, отображаемый в названии Discord канала

**Описание:**
- Автоматически обновляемое значение, которое отображается в названии канала Discord
- Обновляется на основе агрегированных данных из ClickHouse
- Поддерживает шаблоны форматирования (templates)

**Типы каунтеров:**
- **Stat** — статистический счётчик (например, общее количество участников, онлайн участников)
- **Goal** — счётчик цели (отображает прогресс к определённой цели, например, "1000/5000 участников")
- **Clock** — временной счётчик (отображает время, например, "День 42")

**Пример:** Канал с названием "👥 Участников: 1,234" — это каунтер типа Stat

---

### Shard (Шард)
**Определение:** Отдельный экземпляр подключения бота к Discord Gateway

**Описание:**
- Discord требует разделения больших ботов на несколько шардов для распределения нагрузки
- Каждый шард обрабатывает подмножество гильдий
- Система должна отслеживать состояние каждого шарда (online, handshaking, disconnected, error)
- ShardManager управляет всеми шардами бота

**Контекст использования:**
- Мониторинг состояния шардов через Admin API
- Перезапуск шардов при необходимости
- Отслеживание производительности каждого шарда

---

### Widget (Виджет)
**Определение:** Встраиваемый компонент для отображения статистики гильдии на внешних сайтах

**Описание:**
- HTML/JavaScript компонент, который можно встроить на любой веб-сайт
- Отображает статистику Discord сервера (количество участников, онлайн, активность и т.д.)
- Настраиваемый внешний вид и тип отображаемых данных
- Обновляется в реальном времени или с определённой периодичностью

**Использование:**
- Владельцы серверов могут размещать виджеты на своих сайтах
- Публичная демонстрация статистики сервера
- Привлечение новых участников

---

### Ingestor (Ингestor / Воркер ингестии)
**Определение:** Фоновый воркер, который переносит данные из Redis Stream в ClickHouse

**Описание:**
- Компонент системы обработки событий
- Читает события из Redis Stream (куда их записывает Bot Service)
- Выполняет батчинг (пакетную обработку) для оптимизации записи в ClickHouse
- Обрабатывает Backpressure (защита от перегрузки при недоступности ClickHouse)

**Поток данных:**
```
Discord Gateway → Bot Service → Redis Stream → Ingestor Worker → ClickHouse
```

**Особенности:**
- Анонимизация данных перед записью (Privacy First)
- Обработка ошибок и повторные попытки
- Мониторинг производительности и задержек

---

### Materialized View (Материализованное представление)
**Определение:** Предварительно вычисленное агрегированное представление данных в ClickHouse

**Описание:**
- Специальный тип таблицы в ClickHouse, которая автоматически обновляется при вставке данных в исходную таблицу
- Используется для оптимизации запросов аналитики
- Хранит агрегированные данные (суммы, средние значения, группировки)

**Примеры Materialized Views в системе:**
- `mv_daily_activity` — дневная активность по гильдиям
- `mv_role_stats` — статистика по ролям
- `mv_heatmap` — данные для heatmap активности
- `mv_command_stats` — статистика использования команд
- `mv_leaderboard` — данные для рейтингов

**Преимущества:**
- Быстрые запросы аналитики (данные уже агрегированы)
- Автоматическое обновление при поступлении новых данных
- Оптимизация использования ресурсов

---

### Bot Token (Токен бота)
**Определение:** Секретный ключ для аутентификации бота в Discord API

**Описание:**
- Уникальный токен, выдаваемый Discord при создании бота
- Используется для всех взаимодействий с Discord API
- Должен храниться в зашифрованном виде (AES-256-GCM)
- При компрометации токена требуется немедленная замена

**Безопасность:**
- Шифрование при хранении в базе данных
- Никогда не передаётся в API ответах
- Управление ключами шифрования через отдельный сервис

---

### Team (Команда)
**Определение:** Группа пользователей, совместно работающих над гильдиями

**Описание:**
- Позволяет нескольким пользователям управлять одними и теми же гильдиями
- Имеет систему ролей: Owner, Admin, Member
- Управление доступом к ресурсам на основе ролей

**Роли в команде:**
- **Owner** — владелец команды, полный доступ
- **Admin** — администратор, может управлять участниками и настройками
- **Member** — участник, может просматривать и использовать ресурсы команды

---

### Subscription Tier (Уровень подписки)
**Определение:** План подписки, определяющий доступные функции и лимиты

**Типы подписок:**
- **Free** — бесплатный план с базовыми функциями
- **Pro** — платный план с расширенными возможностями
- **Enterprise** — корпоративный план с максимальными лимитами и приоритетной поддержкой

**Влияние на функциональность:**
- Количество гильдий
- Количество каунтеров
- Доступ к расширенной аналитике
- Лимиты на использование API

---

### Event (Событие)
**Определение:** Событие, полученное от Discord Gateway

**Описание:**
- События от Discord (сообщения, реакции, голосовая активность и т.д.)
- Обрабатываются Bot Service и записываются в Redis Stream
- Затем переносятся в ClickHouse через Ingestor
- Используются для генерации аналитики

**Примеры событий:**
- `MESSAGE_CREATE` — создание сообщения
- `MESSAGE_REACTION_ADD` — добавление реакции
- `VOICE_STATE_UPDATE` — изменение состояния голосового канала
- `GUILD_MEMBER_ADD` — добавление участника

---

### Rate Limiter (Ограничитель частоты запросов)
**Определение:** Механизм ограничения частоты запросов к Discord API

**Описание:**
- Discord API имеет лимиты на количество запросов (например, 2 обновления канала в 10 минут)
- Rate Limiter контролирует соблюдение этих лимитов
- Использует Redis для распределённого рейт-лимитинга (если ботов много)
- Предотвращает блокировку ботов из-за превышения лимитов

---

### Backpressure (Обратное давление)
**Определение:** Механизм защиты системы от перегрузки при недоступности или медленной работе компонентов

**Описание:**
- Когда ClickHouse недоступен или работает медленно, Ingestor должен обрабатывать накопление событий в Redis
- Стратегии обработки Backpressure:
  - Буферизация в Redis
  - Приоритизация критических событий
  - Оповещения о проблемах
  - Graceful degradation (постепенное снижение функциональности)

---

## Сокращения и аббревиатуры

- **API** — Application Programming Interface (Программный интерфейс приложения)
- **OLAP** — Online Analytical Processing (Онлайн аналитическая обработка)
- **JWT** — JSON Web Token (Токен веб-приложения)
- **OAuth2** — протокол авторизации
- **HTTP** — HyperText Transfer Protocol
- **REST** — Representational State Transfer (архитектурный стиль API)
- **JSON** — JavaScript Object Notation (формат данных)
- **UUID** — Universally Unique Identifier (уникальный идентификатор)
- **ISO 8601** — стандарт формата даты и времени
