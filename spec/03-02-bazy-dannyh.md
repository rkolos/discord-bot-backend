# 3.2. Базы данных

> **Важное примечание:** Перед началом реализации необходимо детально изучить всю документацию в папке `ABOUT/` и её подпапках (`API_SPEC_ADMIN`, `API_SPEC_FRONT`), а также ознакомиться с уже описанными пунктами в папке `spec/` для полного понимания контекста и текущих архитектурных решений.

## Общие требования

- **Изоляция окружений:** для `dev`, `stage`, `prod` должны использоваться раздельные инстансы БД и отдельные учетные данные.
- **Сетевой доступ:** доступ к БД разрешен только из внутренней сети/VPC. Публичный доступ запрещен.
- **Бэкапы:** регулярные резервные копии с контролем целостности и проверкой восстановления.
- **Мониторинг:** метрики доступности, задержек и нагрузки должны быть доступны для админки и алертинга.

## PostgreSQL (Transactional Layer)

- **Версия:** 15+.
- **Назначение:** транзакционные данные (пользователи, гильдии, настройки, биллинг).
- **Доступ:** отдельные роли для чтения/записи, минимальные привилегии.
- **Репликация:** master + read-replica для масштабирования чтения (при необходимости).
- **Бэкапы:** ежедневные снапшоты, хранение не менее 7 дней.
- **Окружения:** отдельные базы/схемы для `dev`, `stage`, `prod`.

## ClickHouse (Analytical Layer)

- **Версия:** актуальная стабильная (LTS).
- **Назначение:** хранение событий и агрегатов аналитики.
- **Доступ:** только чтение для Frontend API и Admin API; запись — через Ingestor Worker.
- **Репликация:** при росте нагрузки — распределенная конфигурация с репликацией.
- **Политика хранения:** сырые события — ограниченный срок хранения (например, 90 дней), агрегаты — дольше.
- **Бэкапы:** регулярные бэкапы на уровне таблиц/партиций.

## Redis (Cache & Message Broker)

- **Версия:** 6+.
- **Назначение:** кэш, Redis Stream, BullMQ очереди.
- **Доступ:** отдельные базы/ключевые префиксы для изоляции сервисов и окружений.
- **Надежность:** включить persistence (AOF/RDB) для критичных потоков.
- **Масштабирование:** при необходимости — Redis Cluster или Sentinel.

## Раздельные адреса API

- **Frontend API** доступен по публичному адресу и использует отдельный базовый URL.
- **Admin API** доступен только из внутренней сети/VPN и имеет отдельный базовый URL.
- Базовые URL для обоих API задаются через переменные окружения.
