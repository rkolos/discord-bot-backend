## Детализация компонентов

### 1. Frontend API Service (NestJS)
- **Назначение**: Основной шлюз для взаимодействия с пользователями. Обрабатывает запросы от веб-интерфейса.
- **Технологии**: NestJS, TypeScript, JWT, Passport.
- **Протоколы**: HTTP/REST (JSON).
- **Взаимодействие**:
  - Чтение/запись данных в **PostgreSQL** (профили, настройки гильдий).
  - Чтение агрегатов из **ClickHouse** (статистика для графиков).
  - Постановка задач в **Redis (BullMQ)** для фоновой обработки.
- **Особенности**: Доступен из публичной сети. Разделен с Admin API (разные адреса/порты).

### 2. Admin API Service (NestJS)
- **Назначение**: Управление системой, мониторинг состояния, администрирование пользователей и гильдий.
- **Технологии**: NestJS, TypeScript.
- **Протоколы**: HTTP/REST (JSON).
- **Взаимодействие**:
  - Полный доступ к **PostgreSQL** и **ClickHouse**.
  - Мониторинг очередей в **Redis**.
  - Прямое управление шардами через Bot Service.
- **Особенности**: **Закрыт под VPN**. Недоступен из публичного интернета. Развернут на отдельном домене/порту.

### 3. Bot Service (Discord.js)
- **Назначение**: Подключение к Discord Gateway, получение событий от серверов, выполнение команд.
- **Технологии**: Node.js, Discord.js.
- **Потоки данных**: 
  - Получает события (Message, Join, Leave) через WebSocket.
  - Отправляет сырые события в **Redis Stream**.
  - Принимает команды на обновление каунтеров через Redis.

### 4. Ingestor Worker
- **Назначение**: Высокопроизводительный перенос данных из очередей в аналитическую базу.
- **Технологии**: Node.js/TypeScript.
- **Потоки данных**: 
  - Читает события из **Redis Stream**.
  - Производит пакетную вставку (Batch Insert) в **ClickHouse**.
  - Выполняет минимальную предобработку/анонимизацию.

### 5. Background Worker (BullMQ)
- **Назначение**: Выполнение тяжелых или отложенных задач.
- **Задачи**:
  - Обновление каунтеров (Stat/Goal/Clock) в названиях каналов Discord.
  - Рассылка уведомлений.
  - Регулярная синхронизация данных.
- **Взаимодействие**: Использует **Redis** как брокер задач.

### 6. Хранилища данных
- **PostgreSQL**: Хранение структурированных транзакционных данных (пользователи, настройки, биллинг).
- **ClickHouse**: Хранение и агрегация больших объемов событий (сообщения, голосовая активность).
- **Redis**: 
  - Брокер сообщений (Streams) для Ingestor.
  - Очереди задач (BullMQ) для Background Worker.
  - Кэширование сессий и часто используемых данных.

## Разделение API сервисов

Для обеспечения безопасности и отказоустойчивости, API разделены на два независимых приложения:

| Характеристика | Frontend API Service | Admin API Service |
| :--- | :--- | :--- |
| **Доступность** | Публичный интернет | Только через VPN |
| **Адрес (Пример)** | `api.server.ninja` | `admin-api.internal.server.ninja` |
| **Порт** | 3000 | 3001 |
| **Аутентификация** | Discord OAuth2 / JWT | Internal Auth / Admin JWT |

## Потоки данных (Data Flow)

1.  **Сбор статистики**: `Discord Gateway -> Bot Service -> Redis Stream -> Ingestor -> ClickHouse`.
2.  **Обновление каунтеров**: `Background Worker -> Discord REST API`.
3.  **Управление**: `Frontend/Admin API -> Redis/DB -> Bot Service -> Discord API`.
