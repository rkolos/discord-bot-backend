# 8.3. Rate Limiting API

> **Важное примечание:** Перед началом реализации необходимо детально изучить всю документацию в папке `ABOUT/` и её подпапках (`API_SPEC_ADMIN`, `API_SPEC_FRONT`), а также ознакомиться с уже описанными пунктами в папке `spec/` для полного понимания контекста и текущих архитектурных решений.

Раздел описывает требования к ограничению частоты запросов API.

## 8.3.1 Общий подход

- Использовать `ThrottlerGuard` (NestJS) как базовый механизм.
- Ограничения должны применяться для Frontend API и Admin API.
- Для масштабирования использовать Redis‑based storage.

## 8.3.2 Базовые лимиты

- Рекомендуемое значение по умолчанию: **100 req/min** на IP или токен.
- Для критических эндпоинтов допускается более строгий лимит.
- Конкретные значения должны быть конфигурируемыми через env.

## 8.3.3 Поведение при превышении

- Возвращать `429 Too Many Requests`.
- Ошибка в формате Envelope (см. пункт 5.2) с кодом `RATE_LIMIT_EXCEEDED`.
