# 10.3. Конфигурация

> **Важное примечание:** Перед началом реализации необходимо детально изучить всю документацию в папке `ABOUT/` и её подпапках (`API_SPEC_ADMIN`, `API_SPEC_FRONT`), а также ознакомиться с уже описанными пунктами в папке `spec/` для полного понимания контекста и текущих архитектурных решений.

Раздел фиксирует требования к управлению конфигурацией.

## 10.3.1 ConfigModule

- Использовать `ConfigModule` (NestJS) как единый источник конфигурации.
- Конфигурация должна читаться из переменных окружения.

## 10.3.2 Валидация env

- При старте приложения выполнять валидацию env через **Joi** или **Zod**.
- При отсутствии обязательных переменных приложение не должно стартовать.

## 10.3.3 Минимальный набор переменных

- Базовые URL для Frontend API и Admin API.
- Подключения к PostgreSQL, Redis, ClickHouse.
- Ключи шифрования (AES‑256‑GCM):
  - **`ENCRYPTION_KEY_V1`** — ключ для шифрования/расшифровки токенов (AES-256-GCM); версионирование в имени переменной соответствует префиксу `v1:` в формате хранения (см. `spec/08-01-shifrovanie.md`).
- **`ADMIN_VPN_SUBNET`** — (опционально) CIDR или список допустимых подсетей для валидации источника запросов к Admin API; дополнительный слой проверки на уровне приложения (например, после reverse proxy). Если переменная задана, приложение может отклонять запросы, пришедшие не из указанной подсети.
- **`HISTORY_SCAN_DEPTH`** — глубина поиска сообщений при импорте истории (число сообщений на канал, например 500). Диапазон 100–500 (при валидации допускается 100–1000).
- **`HISTORY_CONCURRENCY`** — количество каналов, обрабатываемых параллельно в одной задаче импорта истории, чтобы не превышать лимиты Discord API (снижение риска 429). При валидации допускается диапазон 1–10.
