# 5.5. Спецификация методов

> **Важное примечание:** Перед началом реализации необходимо детально изучить всю документацию в папке `ABOUT/` и её подпапках (`API_SPEC_ADMIN`, `API_SPEC_FRONT`), а также ознакомиться с уже описанными пунктами в папке `spec/` для полного понимания контекста и текущих архитектурных решений.

Раздел фиксирует требования к реализации контроллеров строго по спецификациям API.

## 5.5.1 Источники истины

- **Frontend API:** `ABOUT/API_SPEC_FRONT/`
- **Admin API:** `ABOUT/API_SPEC_ADMIN/`

Каждый эндпоинт, параметры, типы и форматы ответов **должны строго соответствовать** указанным файлам.

## 5.5.2 Разделение приложений

- Frontend API и Admin API реализуются как **отдельные NestJS приложения**.
- Никакого смешивания маршрутов и контроллеров между приложениями.
- Админские эндпоинты не должны быть доступны в публичном API.

## 5.5.3 Соответствие маршрутов

- Префиксы и пути (`/api/...`) должны совпадать с документацией.
- HTTP‑методы должны соответствовать спецификациям.
- Параметры запроса и тела должны соответствовать DTO из спецификаций.

## 5.5.4 Изменения спецификаций

- Любые изменения в API должны сопровождаться обновлением соответствующих файлов `API_SPEC_*`.
- Нельзя добавлять/изменять эндпоинты без синхронного изменения документации.
