# 3.1. Язык и фреймворк

> **Важное примечание:** Перед началом реализации необходимо детально изучить всю документацию в папке `ABOUT/` и её подпапках (`API_SPEC_ADMIN`, `API_SPEC_FRONT`), а также ознакомиться с уже описанными пунктами в папке `spec/` для полного понимания контекста и текущих архитектурных решений.

## Требуемый стек

- **Node.js**: версия v20+.
- **TypeScript**: строгая типизация для всех модулей.
- **Фреймворк**: NestJS как основной каркас приложения.

## Формат проекта

- **Монорепозиторий (NestJS Monorepo)** — обязательный формат для текущего проекта.
- В монорепозитории должны быть **два независимых приложения**:
  - **Frontend API Service** (публичный адрес).
  - **Admin API Service** (внутренний адрес, доступ только через VPN).
- Общие сущности, DTO, гварды, фильтры ошибок и утилиты размещаются в shared‑библиотеках и переиспользуются обоими сервисами.

## Раздельные адреса API

- **Frontend API** должен быть доступен из публичной сети по отдельному адресу (например, `api.server.ninja`).
- **Admin API** должен быть доступен только из внутренней сети/VPN и размещён по другому адресу (например, `admin-api.internal.server.ninja`).
- Базовые URL для Frontend API и Admin API настраиваются через переменные окружения, чтобы клиенты обращались к разным адресам.
