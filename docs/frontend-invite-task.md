# Задача для фронтенда: Экран приёма invite по ссылке

## Контекст

Backend реализовал invite-by-link: приглашение без email. Приглашающий создаёт invite (опционально указывает имя приглашённого), получает ссылку `{FRONTEND_BASE_URL}/invite/{inviteToken}` и передаёт её приглашённому любым способом. Приглашённый переходит по ссылке будучи залогиненным и принимает приглашение.

## API

- **GET /api/invites/:token** (публичный, без auth) — предпросмотр invite. Ответ: `{ data: { companyName, inviterName, role } }`. Ошибки: 404 INVITE_NOT_FOUND, 410 INVITE_EXPIRED.
- **POST /api/me/team/accept** (требует JWT) — принять invite. Body: `{ inviteToken: string }`. Ответ: `{ data: { companyId, companyName } }`. Ошибки: 404, 410, 409 ALREADY_TEAM_MEMBER.

## Задачи

1. **Маршрут**
   - Добавить route `/invite/:token`, который парсит token из URL.

2. **Страница invite**
   - При загрузке вызвать `GET /api/invites/:token` (публичный, без auth).
   - Если invite не найден или истёк — показать соответствующее сообщение.
   - Если найден — показать текст: «Вас приглашают в команду [companyName] от [inviterName] с ролью [role]».
   - Кнопки: «Принять», «Отклонить» (или закрыть).

3. **Обработка «Принять»**
   - Если пользователь не залогинен — редирект на логин с `redirect_uri=/invite/{token}`.
   - После логина — вернуться на `/invite/:token` и вызвать `POST /api/me/team/accept` с `{ inviteToken }`.
   - При успехе — редирект в дашборд или страницу команды (например, `/team` или `/companies/{companyId}/guilds`).
   - При ошибках (уже в команде, invite истёк и т.д.) — показать сообщение пользователю.

4. **UI создания invite**
   - Обновить форму invite: вместо email — опциональное поле «Имя приглашённого» (для заметки).
   - После успешного создания invite показать и предложить скопировать `inviteUrl` из ответа API.

5. **Переменная окружения**
   - Убедиться, что `FRONTEND_BASE_URL` (или аналог) используется для формирования ссылок, если нужно.
