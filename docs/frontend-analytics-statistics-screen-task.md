# Задача для фронтенда: Экран статистики с фильтрацией, таблицей и графиками

## Контекст

Администраторам Discord-серверов нужен единый экран аналитики: обзор ключевых метрик, графики по периоду, таблица событий с фильтрами и при необходимости — детальные отчёты (топ каналов, участников, тепловая карта). Бэкенд уже отдаёт все нужные данные; задача — собрать экран, выбрать период, применить фильтры и отобразить таблицу и графики.

**Целевой пользователь:** владелец или администратор гильдии (доступ по JWT + права на гильдию).

---

## Полезные отчёты для Discord-администраторов

1. **Сводка (Overview)** — сообщений за период, активные участники (24ч / 7д). Быстрый ответ «как живёт сервер».
2. **Активность по дням** — сообщения, уникальные участники, минуты в голосе по дням (линейный график). Период задаётся пользователем.
3. **События по типам** — график по типам событий (сообщения, вход/выход участников, создание веток, голос и т.д.) с группировкой по дню/неделе/месяцу. Показывает, что именно происходит на сервере.
4. **Таблица событий** — постраничный список сырых событий с фильтрами по типу, каналу и периоду. Для разбора инцидентов и детального просмотра.
5. **Топ каналов** — по сообщениям и по минутам в голосе (уже есть в combined analytics).
6. **Топ участников** — по сообщениям и голосу (уже есть).
7. **Тепловая карта** — день недели × час (когда сервер наиболее активен).
8. **Распределение по ролям** — активность по ролям (если есть в combined).

---

## API (доступно на бэкенде)

Все эндпоинты: `GET /api/guilds/:guildId/...`, авторизация: Bearer JWT, нужны права администратора гильдии. Период везде задаётся `from` и `to` в формате **YYYY-MM-DD** (обязательны, где указано). Ограничение по тарифу: количество дней в периоде не должно превышать лимит плана (при превышении — 400 INVALID_DATE_RANGE).

### Сводка и общая аналитика

| Метод | Описание | Ответ |
|-------|----------|--------|
| **GET /api/guilds/:guildId/analytics/overview** | Сводка: сообщения за 30 дней, активные за 24ч и 7д | `data: { totalMessages, activeMembers24h, activeMembers7d }` |
| **GET /api/guilds/:guildId/analytics** | Полная аналитика за период (from, to, timezone?) | `data: { timeSeries, heatmap, summary, topChannels, topMembers, roleDistribution, topCommands }` |
| **GET /api/guilds/:guildId/analytics/activity-chart** | График активности по дням (from, to, period?, timezone?) | `data: [{ date, messages, members, voiceMinutes }]` |
| **GET /api/guilds/:guildId/heatmap** | Тепловая карта (день недели × час) | `data: [{ dayOfWeek, hour, value }]` |
| **GET /api/guilds/:guildId/analytics/top-members** | Топ участников (sortBy?, limit?) | `data: [{ id, username, discriminator, avatar, messages, voiceMinutes }]` |
| **GET /api/guilds/:guildId/leaderboard** | Лидерборд с пагинацией (page, pageSize, sortOrder?) | `data: { entries: [...], pagination }` |

### События по типам и поиск

| Метод | Описание | Query | Ответ |
|-------|----------|-------|--------|
| **GET /api/guilds/:guildId/analytics/event-types** | Список типов событий для фильтров и настроек | — | `data: string[]` |
| **GET /api/guilds/:guildId/analytics/events-timeseries** | Временной ряд по типам событий | from, to, groupBy? (day\|week\|month), eventTypes? (массив), timezone? | `data: [{ date, eventType, count }]` |
| **GET /api/guilds/:guildId/analytics/events** | Поиск событий с фильтрами и пагинацией по курсору | from, to, eventTypes?, channelId?, limit? (1–100, по умолчанию 50), cursor? | `data: [...], nextCursor?: { eventId, eventTime }` |

**Формат элемента в `data` для GET .../analytics/events:** `{ eventId, eventTime (ISO 8601), eventType, channelId | null, channelName | null, payloadSummary? }`. Поле `channelName` — название канала из Discord; если канал не найден или событие без канала — `null`. Следующая страница: передать в query тот же `from`, `to`, фильтры и `cursor` из `nextCursor`.

**Список типов событий:** использовать `GET .../analytics/event-types` для селектов фильтра и экрана настроек. Альтернатива — захардкодить список (MESSAGE_CREATE, MESSAGE_UPDATE, MESSAGE_DELETE, GUILD_MEMBER_ADD, GUILD_MEMBER_REMOVE, GUILD_MEMBER_UPDATE, VOICE_STATE_UPDATE, THREAD_CREATE, GUILD_CREATE, GUILD_DELETE, PRESENCE_UPDATE).

### Настройки гильдии (что пишется в аналитику)

| Метод | Описание |
|-------|----------|
| **GET /api/guilds/:guildId/settings** | В ответе есть `analyticsEventTypesBlacklist` — типы событий, которые **не** пишутся в ClickHouse (по умолчанию `["PRESENCE_UPDATE"]`). |
| **PATCH /api/guilds/:guildId/settings** | В body можно передать `analyticsEventTypesBlacklist`: массив типов (из event-types) или `[]`/не передавать для сброса на дефолт. |

## Задачи для фронтенда

### 1. Маршрут и выбор гильдии

- Экран статистики доступен по маршруту вида `/guilds/:guildId/analytics` (или `/guilds/:guildId/stats` — по соглашению с продуктом).
- `guildId` в URL — внутренний UUID гильдии или Discord Snowflake (бэкенд принимает оба). При отсутствии прав — 404 GUILD_NOT_FOUND.

### 2. Выбор периода

- Общий выбор периода (from, to) для всех блоков, где он применим: календарь или два поля даты (YYYY-MM-DD).
- Учесть ограничение по тарифу: при ошибке 400 INVALID_DATE_RANGE показать сообщение о лимите дней.
- Опционально: пресеты «Последние 7 дней», «Последние 30 дней», «Последний месяц» и т.п., подставляющие from/to.

### 3. Блок «Сводка» (Overview)

- Вызвать `GET /api/guilds/:guildId/analytics/overview` (при необходимости с timezone из настроек гильдии).
- Отобразить карточки: всего сообщений (за 30 дней), активные участники за 24ч, активные за 7д.

### 4. График «Активность по дням»

- Данные: `GET /api/guilds/:guildId/analytics/activity-chart?from=...&to=...` (и при необходимости period, timezone).
- Ось X — дата, оси/серии: сообщения, уникальные участники, минуты в голосе. Пустые дни отдаются с нулями — отображать нули, а не пустой график.

### 5. График «События по типам»

- Список типов для фильтра: `GET /api/guilds/:guildId/analytics/event-types` (один раз при загрузке или кэшировать).
- Данные: `GET /api/guilds/:guildId/analytics/events-timeseries?from=...&to=...&groupBy=day|week|month` и опционально `eventTypes[]`.
- Фильтр по типам событий: мультиселект из `event-types` (или подмножества «полезных»: сообщения, участники, голос, ветки и т.д.).
- Группировка: день / неделя / месяц (переключатель или селект).
- Отображение: линейный или столбчатый график с разбивкой по типам (например, серия по каждому eventType). Маппинг `date` + `eventType` + `count` в выбранный формат графика.

### 6. Таблица событий

- Список типов для фильтра: `GET /api/guilds/:guildId/analytics/event-types`. Список каналов: `GET /api/guilds/:guildId/channels` (или аналог из контекста гильдии).
- Данные: `GET /api/guilds/:guildId/analytics/events?from=...&to=...` с опциональными `eventTypes[]`, `channelId`, `limit`, `cursor`.
- Колонки: дата/время (eventTime), тип события (eventType), канал — **использовать `channelName` из ответа** (при `null` можно показывать `channelId` или «—»), краткое payloadSummary (если есть).
- Фильтры над таблицей: период (тот же from/to), типы событий (мультиселект из event-types), канал (селект из списка каналов гильдии).
- Пагинация: «Загрузить ещё» или «Следующая страница» — при наличии `nextCursor` повторный запрос с теми же from, to, eventTypes, channelId и `cursor` из ответа.

### 7. Дополнительные отчёты (уже есть в API)

- **Топ каналов и топ участников** — данные есть в `GET /api/guilds/:guildId/analytics` (topChannels, topMembers) или отдельно top-members, leaderboard. Показать блоки/таблицы на том же экране или вкладках.
- **Тепловая карта** — `GET /api/guilds/:guildId/heatmap`. Ось X — час (0–23), ось Y — день недели (0–6), заливка по value.

### 8. Настройки «Какие события сохранять»

- Список типов: `GET /api/guilds/:guildId/analytics/event-types`.
- В настройках гильдии (или отдельный подпункт) отобразить текущий `analyticsEventTypesBlacklist` из `GET .../settings`.
- Редактирование: форма с мультиселектом «Типы событий, которые **не** записывать в аналитику» (список опций — из event-types). Сохранение через `PATCH .../settings` с `analyticsEventTypesBlacklist`. Пустой массив или сброс — «по умолчанию» (только PRESENCE_UPDATE не пишется).

### 9. Ошибки и граничные случаи

- 404 GUILD_NOT_FOUND — «Сервер не найден или нет доступа».
- 400 INVALID_DATE_RANGE — «Неверный период» или «Период превышает лимит вашего тарифа (N дней)».
- Пустые данные (нули, пустые массивы) — не считать ошибкой; показывать нули на графиках и пустую таблицу с подписью «Нет данных за выбранный период».

### 10. Timezone

- Где API поддерживает `timezone` или заголовок `x-timezone` — при наличии настройки часового пояса гильдии или пользователя передавать его, чтобы даты и агрегаты совпадали с ожиданиями админа.

## План разработки фронтенда

Рекомендуемый порядок внедрения:

1. **Инфраструктура:** маршрут `/guilds/:guildId/analytics`, выбор периода (from/to), обработка ошибок доступа и лимитов тарифа.
2. **Сводка:** блок Overview (GET overview) с карточками.
3. **График активности по дням:** GET activity-chart, ось X — дата, серии — сообщения, участники, голос.
4. **Список типов для фильтров:** вызов `GET /api/guilds/:guildId/analytics/event-types` при загрузке экрана; сохранить в state для селектов.
5. **График событий по типам:** GET events-timeseries, фильтр по типам (мультиселект из event-types), groupBy (день/неделя/месяц).
6. **Таблица событий:** GET events с фильтрами (eventTypes, channelId); колонка «Канал» — **channelName из ответа** (бэкенд уже обогащает); курсорная пагинация через nextCursor.
7. **Дополнительные блоки:** топ каналов, топ участников, тепловая карта (данные из combined или отдельных эндпоинтов).
8. **Настройки blacklist:** в экране настроек гильдии — мультиселект типов (из event-types) для «не записывать в аналитику»; GET/PATCH settings.

**API, используемые в плане:**

- `GET .../analytics/event-types` — единый источник списка типов для фильтров и настроек.
- `GET .../analytics/events` — поле `channelName` в каждом событии (обогащение на бэкенде, без доп. запросов каналов на фронте для таблицы).

- Использовать `GET .../analytics/event-types` для селектов фильтра и настроек blacklist.
- Подключить уже существующие блоки: топ каналов, топ участников, тепловая карта — по данным текущего API.
- Добавить в настройки гильдии управление списком типов событий, которые не записываются в аналитику (blacklist), с опциями из event-types.
- Обработать ошибки доступа и лимиты периода по тарифу; пустые данные отображать без падения (нули, пустые таблицы).
