# Приветственные и прощальные сообщения (Welcome / Goodbye)

Описание функционала для фронтенда: зачем нужен, как вызывать API и как лучше показывать в интерфейсе.

---

## Что это

Администратор сервера может настроить **два типа сообщений**, которые бот отправляет в выбранный текстовый канал:

1. **Welcome (приветствие)** — когда новый участник заходит на сервер, бот отправляет в указанный канал сообщение (текст и/или embed).
2. **Goodbye (прощание)** — когда участник выходит с сервера, бот отправляет в указанный канал сообщение (текст и/или embed).

Сообщения настраиваются отдельно для каждого сервера. Текст и поля embed поддерживают **плейсхолдеры**, которые при отправке подставляются реальными данными (имя пользователя, название сервера, количество участников и т.д.).

Это **не** то же самое, что «логи» (member_join / member_leave): логи — фиксированный формат в канале логов; welcome/goodbye — произвольный текст и embed в любом выбранном канале.

---

## Зачем это нужно

- **Онбординг**: приветствие новых участников, краткие правила или ссылки в одном сообщении.
- **Прощание**: фиксация ухода участника в нужном канале (например, для отчётов или модерации).
- **Гибкость**: канал, текст и вид сообщения (простой текст или красивый embed) задаёт администратор.

---

## API для фронтенда

Все запросы требуют авторизации: заголовок `Authorization: Bearer <JWT>`. Доступ только у пользователя с правами администратора гильдии (уже проверяется через `GuildAdminGuard` на бэкенде).

В пути везде используется **Discord ID гильдии** (Snowflake, строка): `guildId` — это `discord_guild_id` сервера (тот же, что в списке гильдий пользователя).

### Приветствие (Welcome)

| Метод | URL | Назначение |
|-------|-----|------------|
| GET | `GET /api/guilds/:guildId/welcome` | Получить текущие настройки приветствия |
| PATCH | `PATCH /api/guilds/:guildId/welcome` | Обновить настройки приветствия |

### Прощание (Goodbye)

| Метод | URL | Назначение |
|-------|-----|------------|
| GET | `GET /api/guilds/:guildId/goodbye` | Получить текущие настройки прощания |
| PATCH | `PATCH /api/guilds/:guildId/goodbye` | Обновить настройки прощания |

`guildId` — Discord ID гильдии (строка, 17–19 цифр).

---

## Формат ответа (GET) и тела (PATCH)

Один и тот же объект в `data` для welcome и goodbye:

```json
{
  "data": {
    "channelId": "1234567890123456789",
    "enabled": true,
    "messageType": "text",
    "contentText": "Привет, {user}! Добро пожаловать на {server}.",
    "contentEmbed": null
  }
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `channelId` | `string \| null` | Discord ID канала, куда отправлять сообщение. `null` — канал не выбран, сообщения не отправляются (даже при `enabled: true`). |
| `enabled` | `boolean` | Включена ли отправка (true) или выключена (false). |
| `messageType` | `string` | Тип сообщения: `"text"` — только текст, `"embed"` — только embed, `"text_and_embed"` — и текст, и embed в одном сообщении. |
| `contentText` | `string \| null` | Текст сообщения. Используется при `messageType` = `text` или `text_and_embed`. Максимум **2000** символов (лимит Discord). |
| `contentEmbed` | `object \| null` | Объект embed. Используется при `messageType` = `embed` или `text_and_embed`. |

Если настроек ещё не было (первый GET), бэкенд отдаёт «дефолт»:

- `channelId: null`, `enabled: false`, `messageType: "text"`, `contentText: null`, `contentEmbed: null`.

### Объект `contentEmbed`

Все поля опциональны. В каждом строковом поле можно использовать плейсхолдеры (см. ниже).

```json
{
  "title": "Добро пожаловать!",
  "description": "Прочитай правила в канале #правила.",
  "color": 5814783,
  "fields": [
    { "name": "Участник", "value": "{user}" },
    { "name": "Всего на сервере", "value": "{memberCount}" }
  ]
}
```

| Поле | Тип | Лимит Discord |
|------|-----|----------------|
| `title` | `string` | 256 символов |
| `description` | `string` | 4096 символов |
| `color` | `number` | 0 … 16777215 (0xFFFFFF), число в десятичном виде |
| `fields` | `array` | До 25 элементов |
| `fields[].name` | `string` | 256 символов |
| `fields[].value` | `string` | 1024 символа |

При PATCH можно передавать только нужные поля; остальные не трогаются. Чтобы отключить embed, передать `contentEmbed: null`. Чтобы сбросить канал — `channelId: null`.

---

## Плейсхолдеры

В `contentText` и во всех строковых полях `contentEmbed` (title, description, name, value) при отправке сообщения бот подставляет:

| Плейсхолдер | Значение |
|-------------|----------|
| `{user}` | Упоминание пользователя (Discord mention), кликабельно в Discord. |
| `{username}` | Отображаемое имя пользователя (или тег, если имени нет). |
| `{userTag}` | Тег (username#discriminator или просто username). |
| `{userId}` | Discord ID пользователя (Snowflake, строка). |
| `{server}` | Название сервера (гильдии). |
| `{memberCount}` | Текущее количество участников на сервере (после входа/выхода). |

Регистр важен: писать именно `{user}`, `{username}`, `{memberCount}` и т.д.

На фронте в форме можно показывать подсказку: «Доступные подстановки: {user}, {username}, {userTag}, {userId}, {server}, {memberCount}» и, по желанию, кнопки «Вставить {user}» и т.п.

---

## Ошибки

- **404 Not Found** — гильдия не найдена или у пользователя нет прав. Тело в формате Envelope, код ошибки `GUILD_NOT_FOUND`.
- **422 / 400** — ошибка валидации (например, неверный `channelId`, слишком длинный текст). Код `VALIDATION_ERROR`, в `details` — ошибки по полям.

Обрабатывать так же, как остальные эндпоинты гильдии (например, настройки логов или счётчиков).

## Как применять в интерфейсе

1. **Где размещать**  
   Логично в настройках сервера (guild settings), рядом с разделом «Логи» или отдельными блоками «Приветствие» и «Прощание».

2. **Данные при открытии**  
   При заходе на настройки гильдии вызвать `GET /api/guilds/:guildId/welcome` и `GET /api/guilds/:guildId/goodbye` (можно параллельно). Рисовать форму по полям `data`.

3. **Выбор канала**  
   Список каналов уже есть из `GET /api/guilds/:guildId/channels`. В форме — выпадающий список (или поиск) с возможностью «Не отправлять» / «Выключено» (соответствует `channelId: null`).

4. **Включение/выключение**  
   Чекбокс или переключатель для `enabled`. Имеет смысл подсказать: «Если канал не выбран, сообщения не отправляются».

5. **Тип сообщения**  
   Три варианта: «Только текст», «Только embed», «Текст и embed» — привязка к `messageType`: `text`, `embed`, `text_and_embed`. В зависимости от выбора показывать поле текста и/или блок редактирования embed (title, description, color, поля).

6. **Текст**  
   Текстовое поле (или textarea) для `contentText` с лимитом 2000 символов и счётчиком. Подсказка с плейсхолдерами.

7. **Embed**  
   Поля: заголовок (256), описание (4096), цвет (число 0…16777215 или выбор цвета + ввод hex), список полей (name 256, value 1024). В каждом строковом поле — подсказка про плейсхолдеры.

8. **Сохранение**  
   По кнопке «Сохранить» — `PATCH /api/guilds/:guildId/welcome` или `PATCH /api/guilds/:guildId/goodbye` с телом из изменённых полей (можно отправлять только изменённые). После успешного ответа обновить локальное состояние из `data` в ответе или повторно запросить GET.

9. **Разделение**  
   Приветствие и прощание — два отдельных блока (два GET, два PATCH), чтобы администратор мог настроить их независимо.

---

## Краткий чеклист интеграции

- [ ] Вызвать GET welcome и GET goodbye при открытии настроек гильдии.
- [ ] Форма: канал (из списка каналов гильдии), включено/выключено, тип сообщения, текст, embed (если нужен).
- [ ] Валидация на фронте: лимиты длины (2000 для текста, 256/4096/1024 для полей embed), цвет 0…0xFFFFFF.
- [ ] Подсказка по плейсхолдерам в полях, где возможна подстановка.
- [ ] Сохранение через PATCH, обработка 404 (GUILD_NOT_FOUND) и VALIDATION_ERROR.
- [ ] Учесть, что `channelId` и `contentEmbed` могут быть `null` (канал не выбран, embed отключён).
