# Задача для фронтенда: Список компаний (воркспейсов) и переключение между ними

## Контекст

Пользователь может состоять в нескольких компаниях (воркспейсах):

- **Собственный воркспейс** — компания, владельцем которой он является (создаётся при регистрации). В нём отображаются серверы, которые он сам добавил.
- **Команды по приглашению** — компании, в которые его пригласили через invite. В каждой такой компании видны серверы, добавленные любым участником этой команды.

Сейчас список гильдий может отображаться либо как «мои серверы» (`GET /api/me/guilds` — только серверы, где пользователь владелец), либо как серверы конкретной компании (`GET /api/companies/:companyId/guilds`). Чтобы пользователь мог выбирать, в каком воркспейсе смотреть серверы, нужен UI: список всех его компаний и переключение между ними.

## API

### GET /api/me/companies

Список компаний (воркспейсов), к которым пользователь имеет доступ: собственные (где он владелец) и те, куда входит по приглашению. Требует JWT.

**Ответ:** `200 OK`
```json
{
  "data": [
    {
      "id": "string (UUID)",
      "name": "string",
      "role": "Owner" | "Admin" | "Member",
      "isOwner": true
    },
    {
      "id": "string (UUID)",
      "name": "string",
      "role": "Member",
      "isOwner": false
    }
  ]
}
```

- `id` — идентификатор компании (для вызова `GET /api/companies/:companyId/guilds`).
- `name` — название воркспейса.
- `role` — роль пользователя в этой компании.
- `isOwner` — признак «я владелец этой компании» (для UI: свой воркспейс vs приглашённый).

### GET /api/me/guilds

Гильдии, где текущий пользователь **владелец** (только «свои» серверы). Требует JWT. Query: `page`, `limit`, `search`.

### GET /api/companies/:companyId/guilds

Гильдии **конкретной компании** (все серверы, добавленные участниками этой компании). Требует JWT. Доступно только если пользователь является участником компании. Query: `page`, `limit`, `search`. Ответ по структуре совпадает со списком гильдий (id, name, icon, status, memberCount, messageCount, lastActivity, ownerId, subscriptionTier, onlineMembers, memberGrowth, banner). При отсутствии доступа: `404` с кодом `COMPANY_NOT_FOUND` («Company not found or access denied»).

## Задачи для фронтенда

### 1. Получение списка компаний

- Добавить вызов `GET /api/me/companies`.
- Сохранять список в состоянии приложения (например, контекст/сторе). Обновлять список после принятия invite (в ответе accept приходит `companyId` и `companyName` — можно добавить новую компанию в список без повторного запроса списка или обновить список целиком).
- Не выводить переключатель списка компаний, если у пользователя доступ только к одной компании (список из `GET /api/me/companies` содержит один элемент).

### 2. Выбор текущего воркспейса (company)

- Хранить выбранную компанию в состоянии (state/URL). Рекомендуется привязать к URL, например:
  - `/guilds` или `/` — «мои гильдии» (как сейчас `GET /api/me/guilds`);
  - `/companies/:companyId/guilds` или `/?companyId=:companyId` — гильдии выбранной компании.
- При первом заходе после логина: по умолчанию выбирать первую компанию из списка (например, собственную, если она есть в списке первая) или «мои гильдии», в зависимости от продуктного решения.

### 3. UI переключателя воркспейсов

- Реализовать компонент переключателя (dropdown / селект / сайдбар): отобразить названия всех компаний из `GET /api/me/companies`. **Не показывать переключатель, если у пользователя доступ только к одной компании.**
- При выборе компании:
  - обновить выбранный companyId в state/URL;
  - загрузить гильдии через `GET /api/companies/:companyId/guilds` и отобразить их в списке серверов.
- Опционально: отдельный пункт «Мои серверы» (только гильдии, где я владелец), ведущий на `GET /api/me/guilds`, если продукт предполагает явное различие между «мои» и «серверы воркспейса». Иначе — показывать только список компаний, и для каждой компании уже показывать гильдии через `GET /api/companies/:companyId/guilds` (в т.ч. для собственного воркспейса).
- В переключателе можно визуально отличать собственную компанию (isOwner: true) от приглашённых (метка «Мой воркспейс», иконка и т.п.).

### 4. Отображение гильдий выбранной компании

- На экране списка серверов:
  - если выбрана компания — использовать `GET /api/companies/:companyId/guilds` с выбранным `companyId`;
  - при ошибке 404 COMPANY_NOT_FOUND — показать сообщение об отсутствии доступа и не подставлять в список данные из кэша другой компании.
- Сохранить существующую пагинацию и поиск (query-параметры `page`, `limit`, `search`) для выбранного источника (me/guilds или companies/:id/guilds).

### 5. Синхронизация с invite

- После успешного `POST /api/me/team/accept` в ответе приходят `companyId` и `companyName`. Либо добавить новую компанию в локальный список компаний, либо перезапросить `GET /api/me/companies` и при желании автоматически переключить интерфейс на новый воркспейс (редирект на `/companies/{companyId}/guilds` или аналог).

### 6. Страница «Команда» (GET /api/me/team)

- Сейчас `GET /api/me/team` возвращает участников **одной** компании (у пользователя — компании, где он владелец). Если в продукте страница «Команда» привязана к выбранному воркспейсу, нужно либо:
  - запрашивать участников для выбранной компании (для этого бэкенду может понадобиться эндпоинт вида `GET /api/companies/:companyId/team`), либо
  - оставить текущее поведение (участники только «своего» воркспейса) и явно указывать на UI, что это «Команда моего воркспейса».

Уточнить с бэкендом и продуктом: нужен ли эндпоинт участников по `companyId` для выбранного воркспейса.

## Итог

- Реализовать получение списка компаний через `GET /api/me/companies`.
- Реализовать переключатель воркспейсов и при выборе компании показывать гильдии через `GET /api/companies/:companyId/guilds`.
- Связать выбор воркспейса с URL/state и с обновлением списка после accept invite.
